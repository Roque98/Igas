📊 Documentación de Base de Datos

Sistema de Mesa de Ayuda iGAS - Esquema de Base de Datos v1.0.0

Archivo SQL: database/schema.sql
Motor: PostgreSQL (Supabase)
Versión: 1.0.0
Última actualización: 11 de enero de 2026

🎯 Descripción General

Este esquema de base de datos proporciona la estructura completa para el sistema de Mesa de Ayuda iGAS, incluyendo gestión de usuarios, clientes, tickets de soporte, y control de SLA.

📋 Estructura de Tablas

1. Catálogos Base

roles

Define los roles de usuario en el sistema.

Campo Tipo Descripción
idUUIDIdentificador único (PK)
nombreTEXTNombre del rol (Administrador, Supervisor, Agente, Cliente)
descripcionTEXTDescripción del rol
permisosJSONBObjeto JSON con permisos del rol
Valores por defecto: Administrador, Supervisor, Agente, Cliente

equipos

Equipos de trabajo o áreas.

Campo Tipo Descripción
idUUIDIdentificador único (PK)
nombreTEXTNombre del equipo
descripcionTEXTDescripción
supervisor_idUUIDID del supervisor (FK profiles)
estatusTEXTActivo/Inactivo

horarios

Horarios/turnos de trabajo.

Campo Tipo Descripción
idUUIDIdentificador único (PK)
nombreTEXTNombre del horario
hora_inicioTIMEHora de inicio
hora_finTIMEHora de fin
dias_semanaTEXT[]Array de días laborales

categorias_servicio

Categorías para clasificar tickets.

Campo Tipo Descripción
idUUIDIdentificador único (PK)
nombreTEXTNombre de la categoría
descripcionTEXTDescripción
sla_minutosINTEGERTiempo SLA en minutos
colorTEXTColor hexadecimal para UI
parent_idUUIDPara categorías jerárquicas (FK self)

estatus_tickets

Estados posibles de un ticket.

Campo Tipo Descripción
idUUIDIdentificador único (PK)
nombreTEXTNuevo, Abierto, En Progreso, Pausado, Resuelto, Cerrado, Cancelado
colorTEXTColor para UI
ordenINTEGEROrden de visualización
es_finalBOOLEANIndica si es un estado final

2. Usuarios y Autenticación

profiles

Extensión de auth.users de Supabase con información adicional del usuario.

Campo Tipo Descripción
idUUIDPK, FK a auth.users(id)
nombre_completoTEXTNombre completo del usuario
emailTEXTEmail (duplicado de auth.users)
rol_idUUIDFK a roles
area_equipo_idUUIDFK a equipos
telefonoTEXTTeléfono de contacto
estatusTEXTActivo/Inactivo
turno_horario_idUUIDFK a horarios
avatar_urlTEXTURL del avatar en Storage
disponibilidadTEXTEn línea, Ocupado, Fuera de turno
configuracionJSONBPreferencias del usuario
Importante: Se crea automáticamente mediante trigger cuando se crea un usuario en auth.users

4. Tickets y Soporte

Tabla principal de tickets de soporte.

Campo Tipo Descripción
idUUIDIdentificador único (PK)

sucursal_idUUIDFK a sucursales (opcional)
categoria_idUUIDFK a categorias_servicio
prioridadTEXTCrítica, Alta, Media, Baja
canalTEXTTeléfono, WhatsApp, Correo, Portal, Presencial
responsable_idUUIDFK a profiles (agente asignado)
equipo_idUUIDFK a equipos

ticket_participantes

Usuarios relacionados con un ticket.

Campo Tipo Descripción
ticket_idUUIDFK a tickets (PK compuesta)
usuario_idUUIDFK a profiles (PK compuesta)
rol_participacionTEXTResponsable, Observador, Colaborador

ticket_adjuntos

Archivos adjuntos de tickets.

Campo Tipo Descripción
idUUIDIdentificador único (PK)
ticket_idUUIDFK a tickets
nombre_archivoTEXTNombre original del archivo

tipo_archivoTEXTMIME type

Timeline/historial de eventos del ticket.

Campo Tipo Descripción
idUUIDIdentificador único (PK)
ticket_idUUIDFK a tickets
usuario_idUUIDFK a profiles

ticket_historial_asignaciones

Historial de reasignaciones de tickets.

⚙️ Funciones y Triggers

handle_new_user()

Crea automáticamente un perfil en profiles cuando se registra un usuario en auth.users.

TRIGGER AFTER INSERT

update_updated_at_column()

Actualiza automáticamente el campo updated_at en tablas relevantes.

TRIGGER BEFORE UPDATE

generar_folio_ticket()

Genera automáticamente el folio del ticket con formato IGAS-YYYYMMDD-XXXX.

TRIGGER BEFORE INSERT

🔒 Row Level Security (RLS)

Todas las tablas principales tienen RLS habilitado. Políticas implementadas:

  • Los usuarios pueden ver y editar su propio perfil
  • Los administradores pueden ver todos los perfiles
  • Los usuarios pueden ver tickets donde son responsables, creadores o participantes
  • Los administradores pueden ver todos los tickets

📊 Vistas

tickets_completos

Vista que une información de múltiples tablas para facilitar consultas:

  • Información completa del ticket
  • Datos del cliente y sucursal
  • Información de categoría y estatus
  • Datos del responsable y creador
  • Cálculo de tiempo transcurrido
  • Cálculo de porcentaje de SLA usado

🚀 Cómo Aplicar el Schema

Opción 1: Supabase Dashboard
1. Ir a SQL Editor en Supabase
2. Copiar el contenido de database/schema.sql
3. Ejecutar el script
Opción 2: CLI de Supabase
supabase db reset
supabase db push

📝 Notas Importantes

  • IMPORTANTE El esquema asume que ya existe la tabla auth.users de Supabase
  • INFO Los folios de tickets se generan automáticamente
  • TIP Los perfiles de usuario se crean automáticamente al registrar un usuario
  • SEGURIDAD Todas las tablas críticas tienen RLS habilitado
